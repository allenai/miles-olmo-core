## Exclusion audit

The tool builds into a fresh object database; raw upstream commits and removed
blobs are never copied there. Both the initial build and an independent rebuild
produce identical mappings for all 451 commits. The mapping's policy digest
excludes only the moving comparison SHA, not any exclusion rule.

The release-merge ancestry audit covers 462 reachable commits, 448 distinct trees
and 5,609 distinct blobs. No path prohibited by the manifest, nonempty exact
excluded blob, or original mapped upstream commit is reachable. Empty package
markers are the only permitted exact-blob overlap. The final maintenance head
is audited again before publication.

The content scan compares 860 excluded blob versions against 5,141 retained
historical blob versions and every filtered commit message. It finds 324 blob
similarity leads and no message matches, using windows of ten normalized,
nonblank, noncomment lines. Review dispositions:

- Launcher/model configuration and generated snapshots share flags, command
  construction and test setup with removed examples. Those common sequences do
  not import the removed model/kernel implementations.
- Fully async rollout shares an import list with the removed verifiers example.
  The F1 reward shares its pre-existing answer-normalization helper with a
  removed example. Both retained implementations predate this update.
- Qwen GDN implementations share calls to the public FLA interface with the
  omitted GLM KDA plugin. The matching windows are argument lists, not copies of
  the omitted implementation. Existing FLA notices remain in place.
- Chat-template tests share request fixtures with the omitted DeepSeek 3.2 test;
  they do not restore the excluded encoder implementation.
- The historical `miles_plugins/models/dsa_topk.py` is the first-party dispatch
  wrapper already present in the original flattened fork. Its later path under
  the broadly excluded `miles/kernels/attention/dsa/` is removed. Keeping the
  already-retained wrapper at its old path does not restore an omitted adapted
  kernel. It is also absent at the final release merge.
- The old `tests/fast-gpu/test_dsv4_1_rope_autograd.py` path was discovered by
  similarity to the excluded moved test. It is now excluded from every imported
  historical tree, as well as its later path. Neither path exists in the reused
  PR #5 source tree or the existing flattened fork history.
- The excluded streaming helper and SSE response branch are removed from every
  historical version of session core; the other session changes remain visible.
  The original Typer helper is omitted from the filtered lineage; the fork's
  reviewed replacement remains in the merge head.

This is an engineering review against the existing exclusion policy. Similarity
search cannot establish absence of rewritten or shorter copied fragments, or
provide a comprehensive licensing determination. Keep the manual content review
in every update; a clean path audit alone is insufficient.

## Validation and outstanding runtime gates

The maintenance/discovery panel passes 18 tests, including deterministic SHA
reproduction, preservation of empty commits and merge parents, an incremental
update retaining the published prefix, refusal of retroactive filter changes,
rejection of excluded code hidden in an intermediate commit, and detection of a
modified copy outside excluded paths.

PR #5's hosted CPU shard 0 exposed one additional collection/runtime dependency
issue: its generic worker-logging check imports `olmo_core` in an environment
where that optional backend is not installed ([failure log](https://github.com/allenai/miles-olmo-core/actions/runs/39723722611/job/119643044075)).
The follow-up adds the same optional-import guard already used for Torchtitan.
The served-worker logging panel passes with Core (11 passed, one Torchtitan skip)
and without Core (10 passed, two explicit optional-backend skips). Core logging
is still asserted whenever Core is installed. No production module is changed.

The reused source carries PR #5's prior CPU evidence (15,794 passed, 96 skipped,
9 expected failures, plus the recorded focused follow-ups) and local 4090
training/resume evidence. The within-run control/resume comparison matched all
560 checkpoint tensors exactly. These are reused results, not newly launched
GPU runs for this history change. Independent cold-container repeatability is
still unresolved. The trained H045 two-GPU gate and production runtime build
remain outstanding; no runtime pin or required GPU CI gate is advanced here.

Merge this proposal with a merge commit or true fast-forward. Squash/rebase
merging would discard the filtered lineage. The next update must use the recorded
mapping and merge the next filtered release; do not attach raw upstream history.
